# Cocos 浏览器连接插件开发计划

状态：首版代码、测试与安装 ZIP 已就绪。Creator 3.8.8 已通过本机 CDP Bridge 2.4.0 读取实际预览页链接。标准 cdp-tunnel 3.6.4 的调试附着与独立工程的面板验收仍待完成。详见 [验收记录](acceptance.md)。

## 目标与边界

在 Cocos Creator 3.8.x 内安装一个插件，通过现成 CDP Bridge 连接本机已打开的 Chrome 页面。用户能够从 Creator 面板或 MCP 客户端选页、连接、确认实际页面、查询状态和断开。

优先验证 Creator 3.8.6，记录其他小版本实际结果。首版以当前 Windows 环境为验收环境，不推断跨平台可用性。

**本期包含：**

- Creator 插件入口、面板与卸载清理。
- 本地 Streamable HTTP MCP 服务、会话、令牌鉴权、权限和最小健康检查。
- 现成 Bridge 的环境检查、目标发现、明确选页、flatten session、身份回读、有界恢复。
- 面板与 MCP 共享活动目标，客户端会话权限隔离。
- 安装说明、构建产物、可复用验收流程和验证记录。

**后续能力：**

- GameView、专用 Chrome、显式外部 CDP 通道、Chrome 原生共存、旧 Companion。
- 完整页面探针、截图、DOM、输入、监控、诊断、证据存储和 Trace。
- 企业策略安装、CRX 签名/更新服务、自动安装与托管 relay；本期先使用外部准备好的 Bridge/relay。

首版不实现 GameView，因此 disconnect 返回未连接，不能沿用完整系统“回到 GameView”的结果。

## 用户操作闭环

1. 按说明安装现成 Bridge、启动 relay，打开目标页面。
2. Creator 打开插件面板，检查 relay 与扩展联通状态，查看实际 MCP 地址。
3. 扫描页面，从列表明确选定目标；也可填写 URL 执行 adopt。
4. 附着后通过页面 session 读取实际标题和 URL，展示目标 ID、通道、端口。
5. MCP 客户端连接并读取同一活动目标；切换后面板同步。
6. 主动断开或卸载插件，调试会话释放，用户 Chrome 和页面仍可使用。

## 最小公开能力

| 工具 | 动作 | 风险/范围 |
| --- | --- | --- |
| system | health | 清理后的服务健康信息 |
| manage_tools | list_groups / activate | 会话可见工具范围；不可提升服务授权上限 |
| browser_connect | list / connect / adopt / status / disconnect | process；runtime 组 |
| browser_page | status | read；只回读 URL、标题及目标身份，不实现其他页面动作 |

增加最小 browser_page status 是为了独立确认真实页面，避免仅把 socket 连通视为成功。准确 Schema、返回类型和权限矩阵在 M1 固定，未实现动作不出现在 tools/list 或面板中。

## 拟建目录

```text
package.json                 Creator 扩展清单、消息、脚本
src/main.ts                  扩展加载、IPC、卸载
src/bootstrap/               配置与实例装配
src/access/http/             HTTP、安全、会话宿主
src/access/mcp/              MCP 注册和结果封装
src/application/             连接业务、工具、权限协调
src/domain/                  目标、状态、端口、错误类型
src/infrastructure/browser/  Bridge 发现、CDP session、恢复
panels/browser/              面板、模板、样式
scripts/                     会话调试、打包与验收入口
tests/                       必要的契约、竞态和集成用例
docs/                        当前资料及后续安装、验收记录
```

这是拟建结构，实际以 Creator 扩展模板和运行时验证结果调整；不复制参考项目全部目录。

## 开发阶段

### M0：验证运行环境与 Bridge 协议

- [ ] 确认本机 Creator 实际版本、插件运行时 Node/Electron 能力，以及 Chrome 版本。
- [ ] 核验现成 CDP Bridge/relay 的可获取版本，选择可复现安装方式并锁定已验证版本。
- [ ] 分别检查 9221/json/browsers、9220/json/version、9220/json/list。
- [ ] 在两个本地测试页中明确选择一个，完成浏览器 socket → flatten 附着 → 标题/URL 回读 → detach。
- [ ] 核验 Tab.getMuteStatus、数字字符串 ID 和 9221/client 回退是否适用于锁定版本。
- [ ] 记录 relay 实际监听地址与独立访问保护；不要用 MCP token 代替 relay 保护。

产出：环境记录、锁定版本、安装启动步骤、协议差异清单。

通过条件：复用现成 Bridge 可以完成已有页面闭环，用户页面保留。此阶段不开发企业策略安装器；需要浏览器授权或管理员安装操作时，依据实际步骤处理。

### M1：固定最小契约与插件骨架

- [ ] 从 Creator 3.8 扩展机制建立 main、菜单、panel、消息和构建入口。
- [ ] 定义目标、状态、连接代次、错误和最小 BrowserCdpPort。
- [ ] 固定五个连接动作与最小页面 status 的 Schema、结果字段、风险策略。
- [ ] 确定 token 配置/生成与保存方式、Host/Origin 规则、空闲回收阈值和关闭超时。
- [ ] 明确权限上限、默认 core 可见工具及 runtime 激活行为；选择足够小的权限模型，不复制无关工具组。
- [ ] 用替身连接服务打通面板和主进程，验证重复开关及卸载。

产出：可加载插件骨架、契约文档、构建命令。

通过条件：独立 Creator 测试项目可加载，面板 IPC 可用，扩展启停没有重复监听。

### M2：实现 MCP HTTP 与会话

- [ ] 只监听 127.0.0.1，在 8765–8785 内选择端口并展示实际地址。
- [ ] 分流 health/mcp，处理鉴权、SDK 初始化及真实会话 ID。
- [ ] 每会话独立 server/transport/访问上下文，记录活动请求及最近访问时间。
- [ ] 注册核心工具与浏览器工具，执行时再次验证 Schema 和权限。
- [ ] 完成会话终止、空闲回收、服务关闭与清理后的日志输出。
- [ ] 提供复用同一真实 HTTP 会话的调试入口。

产出：可连接 MCP 服务、客户端配置示例、会话集成验证记录。

通过条件：两条真实 HTTP 会话的 profile 和执行权限互不影响；终止一条不影响另一条或共享连接；无效凭据被拒绝。

### M3：实现 Bridge 连接与身份验证

- [ ] 目标发现、可选补扫、超时、原始 ID 保留与合理去重。
- [ ] 明确目标 ID 连接；adopt 先按 URL 过滤，再按优先级选页，歧义不猜测。
- [ ] 校验 browser WebSocket 地址，建立 session，区分页面域与浏览器域。
- [ ] 页面命令与事件按 sessionId 隔离，回读真实标题/URL。
- [ ] 原子提交活动连接，失败和晚到结果清理本次新资源。
- [ ] 断开释放 session/socket，保留外部 relay、Chrome 和页面。

产出：Bridge 适配器、共享连接服务、连接工具真实实现。

通过条件：从 MCP 指定两个页面之一并正确回读；同 URL 多页面可按 ID 区分；连接失败有可定位错误，断开后页面保留。

### M4：面板联调与断线恢复

- [ ] 面板显示 URL、端口、目标列表和实际 MCP 地址，提供本期动作。
- [ ] 分层呈现 relay、扩展在线、目标连接状态；缺少证据的安装状态为未知。
- [ ] 双向同步面板与 MCP，维护面板显示代次和主进程连接代次。
- [ ] 首次失败有界重试；已连接后按原目标身份恢复，重复身份不任意选页。
- [ ] 新连接、断开或卸载取消旧恢复任务，迟到结果清理而非覆盖。
- [ ] 面板关闭取消 UI 轮询和监听，保留共享连接；卸载释放插件拥有的全部资源。

产出：完整首版交互、恢复与竞态回归证据。

通过条件：A 连接阻塞时发起 B 或 disconnect，随后 A 返回仍不覆盖最新意图；relay 中断可解释，恢复不串页；重复开关面板不叠加事件。

### M5：验收、审查与交付

- [ ] 运行构建、必要的契约/竞态检查、真实 HTTP 双会话与 Bridge 实机验收。
- [ ] 在独立 Creator 测试项目验证打包安装，不依赖开发机全局依赖。
- [ ] 对真实 Creator Browser Preview 做一次连接与标题/URL 回读，首版不要求引擎诊断字段。
- [ ] 检查包内容、版本元数据、令牌清理、服务绑定和资源所有权记录。
- [ ] 根据 AGENTS.md 使用 ai-code-reviewer 审查；可用独立审查子代理，只给需求、范围及验证证据。
- [ ] 作者逐条核实并修复确认问题，重跑受影响检查；自动审查修复最多三轮。
- [ ] 交付安装包、Bridge 准备说明、MCP 配置、使用说明及验证报告，列明未验证版本和未实现能力。

通过条件：首版必测项全部通过；阻断问题不能靠跳过测试视为完成。环境受限的项目单列未验证，并准确限定交付结论。

依赖顺序：M0 → M1 → M2 → M3 → M4 → M5。阶段清单保留原定验收范围，当前证据见下方进度。

## 验证策略

| 层级 | 核心案例 | 能证明什么 |
| --- | --- | --- |
| 业务/契约 | URL 匹配、歧义、旧 ID、权限、结果封装 | 确定规则与错误语义 |
| 协议替身 | sessionId 隔离、超时、晚到连接清理 | 资源和并发边界 |
| 真实 HTTP | 双会话、鉴权、tools/list 与执行校验 | MCP 会话及权限实际生效 |
| Bridge 实机 | 两页选定、回读、断开、relay 中断 | 现成 Bridge 实际可用 |
| Creator 实机 | 加载、IPC、面板/MCP 同步、重开、卸载 | 编辑器集成与生命周期 |
| 发布验证 | 安装包在独立测试项目加载 | 交付完整性 |

测试须覆盖可观察行为和风险，不编写仅复述实现的机械测试。历史的 240/1/2 和 1/1 成绩不计入本项目验证。

## 契约差异与待核对项

| 事项 | 整理后的处理 |
