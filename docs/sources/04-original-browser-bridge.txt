2. 打开浏览器级 WebSocket，发 Target.attachToTarget({targetId,flatten:true})。relay 把请求转给已连接的扩展。扩展解析目标标识，调用 chrome.debugger 附着，记录 sessionId 到 tab 的映射，再把结果传回。附着路径执行的是已有页签连接。
3. 只有已打开 9220 WebSocket 后执行附着失败，现有实现才关闭该连接，尝试旧版 ws://127.0.0.1:9221/client，并用同一目标 ID 重新附着。版本发现或初次 WebSocket 连接失败会返回给外层处理。日常接管使用 9220，因为 9221/client 与端口池的创建模式共用命名空间。
4. 用 createCdpPageSession 包装浏览器连接和返回的 sessionId。Runtime、Page、Input、Network 等页面命令携带当前会话 ID，订阅的页面事件按相同 ID 过滤。Browser 和 Target 域走浏览器级会话。
5. 路由记录当前目标和通道，结果应为 connected=true、transport=chrome-cdp。让 browser_page status 在该会话读取实际 URL 和标题作为第一次回读。需要持续抓事件时再调用 browser_monitor start。
